# Project instructions

- Whenever you finish implementing code changes, run the appropriate tests and build checks.
- Summarise the files changed and what was implemented.
- After successful validation, create a GitHub pull request containing those changes, if the environment supports PR creation.
- Never automatically merge a pull request into `main`. The user must review and approve changes before merging.
- If PR creation fails or isn't available, explain why and provide the exact next steps.
- Do not create a pull request when you have only answered a question or analysed code without making changes.
